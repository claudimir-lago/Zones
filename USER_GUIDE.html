Zones User Guide

Operational guide for Zones 0.7.4.

1. Starting Zones

Build the project with Java 17+ and Maven (or NetBeans). On Windows, run start_Zones.cmd after packaging. The launcher uses javaw, so the command-prompt window closes after the application starts.

2. Opening data

Use Open to load a minimalistiCE-format file. Detector names follow migration order from the injection point: 1st C4D is reached first and 2nd C4D second, regardless of physical left/right layout.

3. Baseline processing

Set the analysis range, adjust parameters if needed, then choose Calculate baseline.

  • Scale is the characteristic time width of structures considered compatible with a CE peak. Zones shows scales in seconds, although the internal algorithm uses sample counts.
  • K (votes) is the minimum number of scales that must agree that a point belongs to the baseline.
  • Numerical parameters, selective MMR, and charge-recalculation options persist between sessions. Restore defaults returns to program defaults.

4. Time, charge, and mobility

Time

Baseline processing and peak detection are performed in time. Quantitation reports migration time in minutes; the number of decimal places is chosen automatically from the local sampling resolution. Time-domain FWHM remains in seconds and uses the same adaptive-resolution rule.

Charge

Charge is obtained by trapezoidal integration of synchronized current and is displayed in mC with its natural sign. Invert charge axis explicitly plots -Charge (mC). Charge-domain position and FWHM use decimal places chosen automatically from the local charge spacing near each fitted peak.

Mobility

Mobility is reported in Tiselius (Ti), with 1 Ti = 10-9 m² V-1 s-1. Values with |μ| > 1000 Ti are excluded. Quantitation uses an adaptive number of decimal places for mobility position and FWHM, derived from the local mobility spacing near each fitted peak.

Calibration modes are: instrument parameters only (apparent mobility), two effective-mobility standards (effective mobility), and instrument parameters + one effective-mobility reference (effective mobility). Instrumental calibration can use either Charge / conductivity (capillary i.d., BGE conductivity and detector distance) or Voltage / capillary length (signed applied voltage, total capillary length, detector distance and run temperature). The voltage/time route can therefore be used with legacy electropherograms that contain no current or charge data. Values entered for both strategies are retained when switching and persisted between sessions.

5. Peak analysis

The Quantitation table reports domain-specific peak metrics. Rows with R² < 0.99 are highlighted as a visual warning only. Mobility references are assigned directly in the editable Mobility reference, Known μeff (Ti) and μeff temp (°C) cells. Zones records migration time and, when available, migration charge, and uses the coordinate appropriate to the selected calibration basis.

Temperature normalization

For aqueous systems, BGE conductivity and mobility-reference values may be entered at their original measurement temperatures. Zones normalizes inverse-viscosity-dependent quantities to 25 °C before mobility calibration using the water-viscosity model. This is not a universal correction for non-aqueous or hydro-organic media.

User export

Export results can create either a ZIP archive or individual uncompressed files. The export contains a TAB-delimited quantitation.csv with processing/calibration metadata and optional processed electropherograms in time, charge and mobility. Files keep the .csv extension but columns are always separated by TAB. Developer ZIP remains available for detailed diagnostics.

Graph and Quantitation selection

Double-clicking within a fitted component region in the Corrected C4D graph highlights the most likely Quantitation row. A single click remains available for normal graph interaction. If no component covers the double-clicked region, Zones generates a warning.
